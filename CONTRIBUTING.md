# Contributing to VRP

Thank you for your interest in the Veil Routing Protocol (VRP).

This repository contains the public engineering specification of the VRP architecture.

Its purpose is to document observable architectural behavior while protecting proprietary runtime implementation.

---

# Purpose of Contributions

Contributions should improve one or more of the following:

- architectural clarity
- engineering accuracy
- documentation quality
- reproducibility
- readability
- consistency

This repository is not intended for experimental implementation development.

---

# Scope

Appropriate contributions include:

- documentation improvements
- typo corrections
- RFC clarification
- ADR clarification
- Mermaid diagrams
- engineering examples
- evaluation improvements
- public architectural discussion

---

# Out of Scope

The following should not be proposed:

- implementation internals
- protected runtime algorithms
- transport scoring logic
- synchronization mechanisms
- proprietary optimizations
- reverse engineering
- confidential runtime behavior

Protected implementation is intentionally excluded from this repository.

---

# Before Opening an Issue

Please verify:

- the question is not already answered;
- the appropriate RFC has been reviewed;
- the appropriate ADR has been reviewed;
- the Runtime documentation has been consulted.

Many architectural questions are already documented.

---

# Pull Requests

Pull requests should:

- have a clear purpose;
- solve one problem;
- avoid unrelated modifications;
- preserve documentation style;
- preserve architectural terminology.

Small focused contributions are preferred.

---

# Documentation Style

Documentation should be:

- technically accurate;
- implementation-independent;
- deterministic;
- concise;
- reproducible.

Avoid marketing language.

Engineering clarity has priority.

---

# Architectural Principles

Contributions should never contradict:

- Session ≠ Transport
- Correctness Before Availability
- One Canonical Authority
- Deterministic Runtime Decisions
- Replay Protection
- Evidence-First Validation

Architectural consistency has priority.

---

# Licensing

All accepted contributions become part of the public VRP specification under the repository license.

Contributors retain authorship of their individual work where applicable.

---

# Questions

Questions regarding architecture are welcome through GitHub Issues.

Questions regarding protected implementation cannot be answered.
