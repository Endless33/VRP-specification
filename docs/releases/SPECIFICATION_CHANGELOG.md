# Purpose

This document records the evolution of the public VRP specification.

It documents architectural, documentation, and engineering changes to the public specification.

This is **not** a software release log.

It is a specification history.

---

# Versioning Philosophy

The public specification evolves through engineering refinement.

Changes are categorized to improve transparency for reviewers.

Categories include:

- New Documentation
- Architectural Clarification
- Engineering Guidance
- Security Documentation
- Evaluation Documentation
- Integration Documentation

# Compatibility

Documentation revisions are intended to improve understanding of the architecture.

They do not necessarily imply changes to protected runtime implementation.

---

# Engineering Transparency

Significant public specification updates should be documented here.

Minor editorial improvements may not appear individually.

---

# Final Principle

The specification should evolve in a predictable and reviewable manner.

Every major public revision should improve one or more of the following:

- clarity
- engineering accuracy
- reproducibility
- evaluation methodology
- architectural understanding
