# Frequently Asked Questions

**Document Version:** Public v2

**Status:** Public

---

# Why is the specification public?

The architecture is intended to be reviewed, challenged, and understood by engineering teams before deployment decisions are made.

---

# Why isn't the runtime open source?

The production runtime contains proprietary implementation and engineering know-how.

Architectural transparency and implementation disclosure are separate engineering decisions.

---

# Can we evaluate VRP without access to the runtime internals?

Yes.

The public specification, engineering documentation, validation methodology, and observable runtime behaviour are intended to support independent technical evaluation.

---

# Can we perform our own security review?

Yes.

Independent security review is encouraged.

Organizations should evaluate the architecture using their own engineering standards, security requirements, and validation procedures.

---

# Can we perform adversarial testing?

Yes.

Engineering teams are encouraged to perform replay testing, transport migration, network interruption, authority validation, and other relevant evaluation scenarios.

---

# Can we integrate VRP with existing infrastructure?

The Pilot is designed to evaluate integration feasibility.

Deployment decisions should be based on engineering validation rather than assumptions.

---

# Why is there a protected runtime?

The public specification explains the architecture.

The protected runtime contains proprietary implementation details and intellectual property.

---

# Does the public documentation describe everything?

No.

The public documentation explains the architecture, engineering principles, security model, and evaluation process.

Implementation-specific details remain outside the scope of the public specification.

---

# What is expected from Pilot participants?

Engineering evaluation.

Technical review.

Independent validation.

Constructive feedback.

Deployment decisions based on reproducible engineering evidence.

---

# Summary

VRP is intended to be evaluated through engineering review, observable behaviour, and reproducible validation rather than marketing claims or assumptions.
