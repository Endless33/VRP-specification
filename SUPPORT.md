# Support

## Purpose

This document describes how users, engineers and organizations can obtain support regarding the public VRP specification.

Support is provided for the public engineering documentation contained in this repository.

Support does not include access to the Protected Runtime implementation.

---

# Scope of Support

Support is available for topics including:

- architecture
- RFC documents
- ADR documents
- runtime concepts
- security documentation
- engineering principles
- evaluation methodology
- integration guidance
- public documentation

Questions should relate to the published specification.

---

# Out of Scope

Support is not available for:

- proprietary runtime source code
- internal implementation
- transport selection algorithms
- authority implementation
- synchronization mechanisms
- protected optimization logic
- reverse engineering

These topics remain intentionally confidential.

---

# Before Requesting Support

Please review:

- README.md
- RFC Series
- ADR Series
- Architecture Documentation
- Runtime Documentation
- Security Documentation
- Evaluation Documentation
- Integration Documentation

Many technical questions are already answered in the specification.

---

# Reporting Documentation Issues

Documentation improvements are welcome.

Useful reports include:

- incorrect terminology
- ambiguous wording
- broken references
- formatting issues
- missing explanations
- inconsistent architectural descriptions

Whenever possible, reference the affected document and section.

---

# Engineering Questions

Engineering discussions are encouraged when supported by:

- observable runtime behavior
- published specifications
- engineering evidence
- reproducible evaluation

Technical discussions should remain focused on architecture rather than implementation.

---

# Feature Requests

Suggestions for improving the public specification are welcome.

Examples include:

- clearer documentation
- additional diagrams
- new engineering examples
- clarification of existing RFCs
- improved evaluation guidance

Architectural consistency remains the primary consideration.

---

# Security Questions

Security-related questions should follow the guidance described in:

SECURITY.md

Potential security issues should be reported responsibly.

---

# Community Expectations

Constructive engineering discussion is encouraged.

Please:

- remain respectful;
- provide technical context;
- support claims with evidence whenever possible;
- distinguish architectural questions from implementation questions.

Professional collaboration improves the public specification.

---

# Response Expectations

Response times may vary depending on:

- complexity of the question;
- documentation scope;
- engineering review requirements.

Not every request can be answered if it concerns protected implementation details.

---

# Summary

The VRP project supports discussion of its public engineering specification.

The repository exists to promote transparent architectural understanding while preserving the confidentiality of the Protected Runtime.
